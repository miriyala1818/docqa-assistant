Configuring SAML Single Sign-On

Single sign-on (SSO) lets members sign in to Orbitly with their company identity provider instead of a separate password. SSO and SCIM provisioning are available on the Enterprise plan only.

Supported identity providers

Orbitly supports any SAML 2.0 identity provider. Tested configurations are available for Okta, Microsoft Entra ID (formerly Azure AD), Google Workspace and OneLogin.

Setting up SAML SSO

  1. In Orbitly, open Settings > Security > Single sign-on and click Configure SAML.
  2. Copy the Assertion Consumer Service (ACS) URL and Entity ID shown by Orbitly.
  3. In your identity provider, create a new SAML application and paste the ACS URL and Entity ID.
  4. Download the identity provider's metadata XML file and upload it to Orbitly.
  5. Click Test connection and sign in with a test account.
  6. When the test succeeds, turn on Require SSO to make SSO mandatory for all members.

Automatic provisioning with SCIM

SCIM provisioning creates, updates and deactivates Orbitly members automatically when they change in your identity provider. To enable it, open Settings > Security > SCIM, generate a SCIM token and paste the token and the SCIM base URL into your identity provider's provisioning settings.

Troubleshooting SSO

Error ORB-SSO-02 means the signing certificate in Orbitly does not match the identity provider certificate. Upload the latest metadata XML file to fix it. If members see "user not assigned", assign them to the Orbitly application in the identity provider.
